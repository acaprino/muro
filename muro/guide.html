Come funziona il coordinatore

L’IA interpreta la richiesta e il contesto, confronta intenti ed esclusioni e seleziona le capability. Non usa parole chiave per scegliere una skill.

Le linee grigie collegano l’IA alle capability senza prerequisiti dichiarati: sono scelte disponibili, non passi da eseguire tutti. Le frecce blu indicano solo i prerequisiti after, validi sempre. Le frecce arancioni tratteggiate sono prerequisiti condizionati (needs): l’etichetta la riassume in poche parole; la condizione completa si legge cliccando la freccia o il nodo di arrivo, e la valuta l’IA per ogni richiesta; se vale, la capability di partenza entra nel piano prima dell’altra. Il flusso dei dati (reads) non è mostrato nella vista base, perché dipende dal lavoro scelto. Scegliendo un percorso compaiono frecce verdi piene dove chi produce viene prima di chi legge: lì i dati passano davvero. Scegliendo un intento compaiono frecce verdi tratteggiate: output che le capability di quell’intento possono usare o fornire, se l’altra capability è nel piano. Non obbligano a eseguire chi li produce. I tratti blu discontinui e i numeri mostrano un percorso illustrativo, senza introdurre nuovi prerequisiti.

Una capability lavora alla volta. Un solo responsabile per output; conflitti e varianti incompatibili vengono rifiutati. Un prerequisito si salta solo se tutti i suoi output sono già registrati.

Esiti della decisione IA

selected: esegue il percorso validato. Un passo è diretto; più passi richiedono conferma se non già autorizzati.

needs_clarification: pone la domanda necessaria e si ferma. no_match: segnala che il catalogo non copre il risultato e si ferma.

classification-required: l’host deve produrre una decisione IA. Nessuna capability viene eseguita.

Comandi
/__MURO_COMMAND__ <risultato desiderato>

Quando l’host supporta i comandi delle skill; su Claude Code il nome può essere qualificato dal plugin. L’host prepara la classificazione, senza chiederti di conoscere le capability.

Percorso universale, dalla cartella della skill:

python muro.py plan --task "<richiesta>" --project "<progetto>"
python muro.py plan --task "<richiesta>" --project "<progetto>" --classification "classification.json"
python muro.py plan --task "<richiesta>" --project "<progetto>" --classification "classification.json" --confirm
python muro.py resume --project "<progetto>"

Per i passi con mappa, usa gli identificatori restituiti con il passo. Mantieni le stesse opzioni di stack tra le chiamate.

python muro.py record --project "<progetto>" --map-id <map_id> --capability <capability> --outputs "outputs.json"
python muro.py check --project "<progetto>" --map-id <map_id> --capability <capability> --result "result.json"

Ogni controllo registra name, status (pass, fail o not-tested) ed evidence. Per sostituire consapevolmente una mappa: nuova classificazione e plan --new; la conferma archivia le evidenze precedenti. Il browser non esegue comandi.

Strumenti, attivatori e precedenze

I vincoli stack:* indicano compatibilità tecnica, non attivatori testuali. L’host verifica strumenti e autorizzazioni. Gli hook sono descrizioni passive, non vengono installati o attivati automaticamente.

Il passo che richiede una dipendenza mancante gestisce l’installazione prevista. Ordine delle fonti e posizione nel grafo non conferiscono autorità. Solo il coordinatore scrive la mappa e lo stato.
