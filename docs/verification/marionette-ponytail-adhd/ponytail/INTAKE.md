## Scope-preserving adaptations

- Remove the lazy-senior persona, sardonic marketing, fixed English template phrases and compulsory closing lines. Preserve the actual discipline, readable explanation, full requested reports and accurate disclosure of unchecked work and risk.
- The source's lite/full/ultra meanings remain explainable task preferences: execute requested scope and mention a smaller option; use the smallest complete method; or explicitly examine whether scope is justified. Do not promise a persistent mode, global off toggle or configuration write that changes Marionette's fixed native policy. Help says what was adapted.
- The source audit normally displays at most 20 findings with an omitted count. In this package that is a display default; all material risk and explicitly requested full findings remain available through grouping or an appendix. Brevity cannot erase a requested result.
- Reuse is scoped to the existing project and approved artifact. Ponytail cannot replace a selected capability's required engine, design system, pipeline, test gate or owner-approved scope merely to shorten a diff.
- Upstream ASCII bars can be presented as an accurate table or supported chart. Published Ponytail results remain attributed to the published experiment, never described as fresh Marionette measurements.

## Intentionally unselected original-product mechanisms

The full automation report is `automation/analysis.md`; 30 source blobs independently verified there overlap this broader 44-blob evidence set.

- Lifecycle hooks activate full mode, inject source rules and track per-project/shared mode files; default/config persistence and subagent matching belong to original Ponytail control. Their helper hardcodes SKILL.md and original identities, so activating it unchanged would also conflict with Muro's renamed references and router.
- The startup code map is approximate regex evidence, enabled by default, up to 2000 characters and a 3-second child-process budget. It is not required by the selected methods and would scan unrelated sessions. It must never become a semantic classifier.
- Statusline setup may copy/refresh a script and write a nudge marker before suggesting a host settings edit.
- The native Claude band captures tool/turn/session information, tests/reuse estimates, elapsed time/tokens/cost and task names. It writes CSV ledgers and regenerates a board by default, and optionally posts a row to a configured webhook. The URL defaults empty; sendNames defaults true when configured. Hiding the band or turning source mode off does not disable recording.
- Historical import scans Claude transcripts and writes CSVs. It does not generate the HTML board. The native TSX board module depends on Claude's own API and is not expressible as a simple Muro argv hook.
- Original board/export/statusline, mode UI buttons, project-state tracking, imports, webhooks, updater/uninstaller and other-host skill registration are optional original-plugin product outcomes outside the curated method selection. Help names them as upstream-only, never as supported Marionette controls.
- No selected procedure needs these hooks, native modules, flag files, model calls or telemetry. All remain inert inspection evidence; no hook wiring is proposed. This is an explicit intake exclusion, not a claim that upstream lacks them.

## Published benchmark boundaries

The selected report compares three arms over 39 tasks x 5 runs each (585 sessions), using Claude Code CLI 2.1.288, Opus 5.5/default effort, dated 2026-10-07. Agent shell execution was disabled; the harness ran checks afterwards. Reported aggregate ratios are geometric means of per-task medians.

The displayed reduction versus no skill is 53% code lines, 45% output tokens, 26% cost and 41% time. The source reports tests on 98% versus 68% of tasks categorized as requiring them. Hidden correctness checks cover only 18 surgical tasks: 87/90 (96.7%) versus 86/90 (95.6%). No benchmark was run during this intake, and these figures do not estimate savings in Marionette or the current repository.
