# Office Files (read, convert and edit existing files)

Works on Office and PDF files that already exist: reads their structure and text, converts formats and applies structured edits through the `genoffice` engine, keeping the file's own design.

## Behavior

The full version is `<package_root>/scripts/genoffice/SKILL.source.md`. It wins where this body differs, except for the changes listed in the Sources section. Open only the section a step points to.

1. **Check the engine.** Run `genoffice --version` first. If the command is not found, read the one line in `~/.genoffice/launcher` (Windows: `%USERPROFILE%\.genoffice\launcher`), which GenOffice writes on every start, and run `"<dir>/genoffice"` from bash or `"<dir>\genoffice.cmd"` from PowerShell / cmd, quoted, in place of `genoffice`; the default locations when that file is missing are in the original's opening paragraph. If GenOffice is not installed, install it: say in one line what is installed and from where (the release for this platform from https://github.com/genspark-ai/genoffice/releases), run it, then confirm with `genoffice --version`. If the installer needs the user or fails, say which step is theirs and stop this delivery; do not simulate a result or build it another way. Always add `--json` when a program reads the output; read `status`, `error`, `suggestion` and `detail`, never parse `message`.
2. **Read first.** `genoffice info <file>` or `genoffice <domain> read --json` gives the structure: block indexes (docx), `s_<n>` / `e_*` ids and EMU geometry (pptx), sheet names and cell values (xlsx). `sheet read` without `--range` stops at 500 rows and says `truncated: true`: run `--stats` first to size a workbook, `--cols` / `--max-rows` to page through it, `--where formula` for the formulas alone. Use `pdf read --range a-b` when you cannot open the PDF yourself (password-protected, or page sizes and metadata are needed). Never `cat` or `unzip` an Office file. For other read flags (comments, revisions, styles, sections, notes, text caps) open the command's row in "Commands".
3. **Pick the route.**
   - *Source material or a question:* `convert --to md/csv` or `<domain> read --full --json`, not `render` (pixels, not text). Open "Reading the user's files" for the command per format. Nothing is written to the file.
   - *Format change:* `genoffice convert <file> --to <fmt> [--out <path>] [--force]`; the supported pairs are in the `convert` row of "Commands". Not for a content change: edit first, convert after.
   - *Edit:* run `genoffice guide <domain>` (`guide <domain> <op> --json` for one op's schema), then write the ops JSON yourself and run `genoffice <domain> apply <file> --ops <file>`. One cell fix in a workbook: `sheet apply --cells`. Before writing ops, open the item of "Behaviour to know" for that domain (Word, Excel or PowerPoint), and "Limits" for pivots, sparklines, conditional formats and data validation. For a deck follow "Editing an existing deck": use ops, not the staged pipeline, and keep the deck's own design.
   - *Fill a template:* `genoffice merge <template.docx|pptx|xlsx> --data <values.json | inline JSON> --out <path> [--force] [--strict]`; open the `merge` row of "Commands" to read `detail.unresolved_placeholders[]`.
   - *Redline two Word versions:* `genoffice docs compare <original.docx> <revised.docx> --out <redline.docx>`.
   - *External workbook links:* `genoffice sheet links <xlsx> [--update] [--break indices]`, row in "Commands".
   - *Show or point in the editor:* `genoffice open <file> [--slide n [--el e_12] | --block n | --range [Sheet!]B2:D5 | --page n]`, only when the user asks to see it there; `genoffice selection <file> --json` resolves "this one" / "here" before editing.
4. **Apply safely.** Run `apply --dry-run` when the batch is large. Apply is atomic by default: a rejected op comes back as `op_rejected` with the executor's usage line, the file is untouched and `detail.batch` is `{total, applied: 0, failed, skipped}`; fix that op and resend the whole batch. `--best-effort` applies every op that can apply and `--stop-on-error` applies in order up to the first rejection; both write the file and answer `status: "partial"` with exit 0, the lost ops in `detail.failures` and the counts in `detail.batch`. Check `status`, not only the exit code.
5. **Verify, then report the output path.** Three lines per artifact, every time (check, look, report): open the artifact's row in the table of `Before you say "done"`. `check` and `audit` exit 0 whether or not they found something; the findings are in `detail.issues[]`, with a `suggest` op when possible. After a deck edit run `genoffice slides audit deck.pptx --slide n --json` (a longer sentence in the same box overflows), apply the `suggest` ops it returns, then render once more and look.

## Output handoff

For a mapped step, submit them through the coordinator's `record` command with the step's `map_id` and `capability`. ## Specifics

- Structural edits renumber: new `e_*` ids after `addElement`, `s_*` after adding slides, docx block indexes after `insert_content` / `delete_blocks`; ids of edited slide elements change too. Inside one batch indexes are live; before the next batch run `read` again. Revision ids are positional: read again after any edit before `accept_changes` / `reject_changes`.
- `--slide n` of `slides read/audit/render/replace` and op targets `{ "slide": n }` are 0-based, `render --page n` is 1-based, docx block indexes are 0-based. `sheet apply` addresses sheets by the current tab name in the file, spelled as in the tab.
- **Keep the original.** `apply` edits in place unless `--out` is given; write with `--out` when the user wants the original kept. `create`, `convert` and `image` never overwrite and `apply --out` onto an existing file refuses (exit 2, `output_exists`): pick another name, or `--force` when the user asked for replacement. A file open in a GenOffice tab makes `apply` refuse (exit 2, `file_open_in_gui`): ask the user to close the tab, or use `--out other.ext`; `--force` only if the user accepts the editor may overwrite it.
- Losses to report: `convert pptx→pdf` has no text layer; `convert docx→md` drops images (`detail.skipped`), so use `docs read --full` when you need every word; scanned PDF pages have empty text (`convert --to docx` runs OCR). `docs findReplace` skips table cells (use `replace_blocks` on the table block), and unknown HTML tags in `insert_content` are stripped silently (stay inside the restricted set of `guide docs`).
- Excel ops that still need the live editor (`refresh_pivot`, edits to session-created tables and shapes) are refused with the reason.
- Changing text, a picture or one slide is not restyling the whole deck: that is the `applyTheme` op, or a rebuild through the staged path, which is a new deck by `office-deck`. `slides replace --slide n --spec` is for decks the staged pipeline built, not for restyling a deck the user brought.
- `file_not_open_in_gui`: `selection` and `open --el` need the file in a tab; run `genoffice open <file>` first, then ask the user to select. `outside_allowed_roots`: stay inside `GENOFFICE_ALLOWED_ROOTS`, do not try another location. `resource_limit`: do not retry, tell the user.
- Any other `error`: branch on it, do what `suggestion` says, then resend the whole batch; open the table in "When a command fails" for the next command of that value. A successful result may still carry `warnings[]`: read them, report what matters, do not retry.
- **Data leaving the machine:** every command runs headless on the app's own engines; only `search`, `image` and `media` send data off the machine (the query or the referenced file), to the provider configured in GenOffice.

## Checks

- **structure_read_before_edit**: ids, block indexes, sheet names or ranges used by the ops come from a read of the current file, repeated after any structural edit.
- **batch_status_verified**: the result's `status` was read; a `partial` batch lists its lost ops in `file_result`.
- **post_edit_check_clean**: `slides audit`, `sheet check` or `docs check` after the edit shows no new issue, or each one is listed.
- **original_preserved**: no file was overwritten or forced without the user's request; a read-only request changed nothing.
- **conversion_loss_reported**: dropped images, a missing text layer, uncached formulas and other `warnings[]` are reported to the user.
