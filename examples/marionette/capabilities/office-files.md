# Office Files (read, convert and edit existing files)

Works on Office and PDF files that already exist: reads their structure and text, converts formats and applies structured edits through the `genoffice` engine, keeping the file's own design.

## Behavior

Read `<package_root>/scripts/genoffice/skills/genoffice/SKILL.source.md` whole before working. It is the method in the source's own words, and the steps below are an index into it. The sections that govern this capability are "Commands" (all rows except `create`, `search`, `image` and the `skill` row), the rows of "Which command" about an existing deck, workbook or Word document, reading source material, changing the format, seeing a page and pointing the user at a spot, "Behaviour to know", "Workflow", "Pitfalls", "When a command fails", "Before you say "done"", "Reading the user's files", "Editing an existing deck", "Path rules" and "Limits". "Designing a deck" belongs to `office-deck` and creating a new document, workbook or PDF from content to `office-authoring`; they are not run in this step. Where this body and the original differ, the original wins, except for the changes listed in the Sources section below under "Changes for coexistence".

1. **Check the engine.** Run `genoffice --version` first. If the command is not found, GenOffice writes the launcher directory to `~/.genoffice/launcher` (Windows: `%USERPROFILE%\.genoffice\launcher`) on every start: "read that one line and run `"<dir>/genoffice"` from bash or `"<dir>\genoffice.cmd"` from PowerShell / cmd, quoted, in place of `genoffice` below"; the default locations when that file is missing are in the original's first paragraph. If GenOffice is not installed, install it: say in one line what is installed and from where (the release for this platform from https://github.com/genspark-ai/genoffice/releases), run it, then confirm with `genoffice --version`. If the installer needs the user or fails, say which step is theirs and stop this delivery; do not simulate a result or build it another way. "Always add `--json` when a program reads the output"; read `status`, `error`, `suggestion` and `detail`, and "never parse `message`".
2. **Read first.** "`genoffice info` or `genoffice <domain> read --json` to learn the structure: block indexes (docx), `s_<n>` / `e_*` ids and EMU geometry (pptx), sheet names and cell values (xlsx)." Readers: `docs read` (`--comments`, `--revisions`, `--styles`, `--full`), `sheet read` ("`--stats` first to size a workbook, `--cols`/`--max-rows` to page through a wide or long sheet, `--where formula` for the formulas alone"; "without `--range` it stops at 500 rows and says `truncated: true`"), `slides read` (`--slide n --full`), and `pdf read --range a-b` "when you cannot open the PDF yourself (a password-protected file, or page sizes and metadata are needed)". "never `cat` or `unzip` the Office file itself."
3. **Pick the route** from "Which command".
   - *Source material or a question:* "`convert --to md/csv` or `<domain> read --full --json`"; not "`unzip`/`cat` on the Office file; `render` (pixels, not text)". Nothing is written to the file.
   - *Format change:* `genoffice convert <file> --to <fmt> [--out <path>] [--force]`; not for "any content change (edit first, convert after)".
   - *Edit:* "`genoffice guide <domain>` for the op fields (`guide <domain> <op> --json` for one op's schema), then write the ops JSON yourself", then `genoffice <domain> apply <file> --ops <file>`. One cell fix in an existing workbook: `sheet apply --cells`. For a deck follow "Editing an existing deck": "use ops, not the staged pipeline, and keep the deck's own design."
   - *Fill a template:* `genoffice merge <template.docx|pptx|xlsx> --data <values.json | inline JSON> --out <path> [--force] [--strict]`.
   - *Redline two Word versions:* `genoffice docs compare <original.docx> <revised.docx> --out <redline.docx>`.
   - *Show or point in the editor:* `genoffice open <file> [--slide n [--el e_12] | --block n | --range [Sheet!]B2:D5 | --page n]`, "only when the user asks to see it there"; `genoffice selection <file> --json`: "resolve "this one" / "here" from it before editing".
4. **Apply safely.** "`genoffice <domain> apply --dry-run` when the batch is large; a rejected op comes back as `op_rejected` with the executor's usage line — fix that op and resend the whole batch. Atomic by default: on rejection the file is untouched and `detail.batch` is `{total, applied: 0, failed, skipped}`. `--best-effort` applies every op that can apply, `--stop-on-error` applies in order up to the first rejection; both write the file and answer `status: "partial"` (exit 0) with the lost ops in `detail.failures` and the counts in `detail.batch` — a program must check `status`, not only the exit code."
5. **Verify.** "The QA gate below, then report the output path": the row of "Before you say "done"" for the artifact (check, look, report), "Three lines per artifact, every time". After a deck edit: "`genoffice slides audit deck.pptx --slide n --json` after the edit: a longer sentence in the same box overflows; apply the `suggest` ops it returns (they grow or move the box), then render once more and look."

## Specifics

- "Structural edits renumber: new `e_*` ids after `addElement`, `s_*` after adding slides, docx block indexes after `insert_content`/`delete_blocks`": "Inside one batch indexes are live (later ops see earlier results); before the next batch run `read` again." Revision ids "are positional, so read again after any edit before `accept_changes` / `reject_changes`". "Ids of edited elements change: run `slides read` again before a second round of ops."
- "`slides read/audit/render/replace --slide n` and op targets `{ "slide": n }` are **0-based**; `render --page n` is **1-based**; docx block indexes are 0-based". "`sheet apply` addresses sheets by the **current tab name in the file**, spelled as in the tab".
- **Keep the original.** "`apply` edits in place unless `--out` is given; `--out` onto another existing file also needs `--force`." "Write with `--out` when the user wants the original kept." "`create`/`convert`/`image` never overwrite (exit 2, `output_exists`); `apply --out` onto an existing file also refuses": "Pick another name, or `--force` when the user asked for replacement." "GenOffice has the file open in a tab → `apply` refuses (exit 2, `file_open_in_gui`)": "Ask the user to close the tab, or `--out other.ext`; `--force` only if the user accepts the editor may overwrite it."
- Losses to report: "`convert pptx→pdf` has no text layer; `convert docx→md` drops images (`detail.skipped`)": "Use `docs read --full` when you need every word." "`docs findReplace` skips table cells; unknown HTML tags in `insert_content` are stripped silently": "`replace_blocks` on the table block; stay inside the restricted HTML set (`guide docs`)." "scanned pages have empty text (`convert --to docx` runs OCR)".
- "Excel ops that still need the live editor (`refresh_pivot`, edits to session-created tables and shapes) are refused with the reason."
- Changing text, a picture or one slide is not for "restyling the whole deck (`applyTheme` op, or rebuild through the staged path)"; the staged rebuild is a new deck by `office-deck`. "`slides replace --slide n --spec` rebuilds the page from a spec and is for decks the staged pipeline built, not for restyling a deck the user brought."
- `file_not_open_in_gui`: "`selection`/`open --el` need the file in a tab: `genoffice open <file>` first, then ask the user to select".
- `outside_allowed_roots`: "Stay inside `GENOFFICE_ALLOWED_ROOTS`; do not try another location". `resource_limit`: "Do not retry; tell the user".
- On any other error: "Branch on `error`, do what `suggestion` says, then resend the **whole** batch (atomic apply wrote nothing)"; the next command for each `error` value is in the table of "When a command fails". A successful result may still carry `warnings[]`: "Read them, report what matters, do not retry."
- **Data leaving the machine:** "Every command runs headless on the app's own engines; only `search`, `image` and `media` send data off the machine, to the provider configured in GenOffice." `media` sends the referenced file, `search` and `image` the query.

## Checks

- **structure_read_before_edit**: ids, block indexes, sheet names or ranges used by the ops come from a read of the current file, repeated after any structural edit.
- **batch_status_verified**: the result's `status` was read; a `partial` batch lists its lost ops in `file_result`.
- **post_edit_check_clean**: `slides audit`, `sheet check` or `docs check` after the edit shows no new issue, or each one is listed.
- **original_preserved**: no file was overwritten or forced without the user's request; a read-only request changed nothing.
- **conversion_loss_reported**: dropped images, a missing text layer, uncached formulas and other `warnings[]` are reported to the user.
