# Token Economy

Operates TokenEconomizer 0.1.0, which lowers the cost of coding-agent sessions in repositories the user works in often. It learns from finished sessions through three mechanisms: **micro-skills** (short repository facts stated at session start), **tool pruning** (unused tools left out through the host's own settings) and the **loop guard** (a redirect when a turn is stuck in repeated failures). `$TE` below is:

`python "<package_root>/scripts/tokeneconomizer/plugin/scripts/te_bootstrap.py" cli --cwd "<project root>"`

Add `--host codex`, `--host copilot` or `--host pi` on those hosts; the default is `claude`. The source's launcher tries the interpreter named by `TE_PYTHON`, then `python3`, then `python`: use the first of those that is Python 3.10 or newer in place of `python` when `python` is not.

## Behavior

0. **Read the originals first.** Before working, read in `<package_root>/scripts/tokeneconomizer/plugin/README.md` the sections `## What to expect`, `## Commands`, `## Settings` and `## Model calls and API keys`, and `## Troubleshooting` when something fails. Before activating or removing the automatic mode (steps 4 and 5) also read in `<package_root>/scripts/tokeneconomizer/docs/PLUGIN.md` the sections `## 1. What it does, hook by hook`, `## 4. State and privacy` and `## 5. Known limitations`, and the paragraphs of `## 3. Verified agent behaviour` for the host in use. They are the source's own words on what each command, setting and hook does. Where this body and an original differ, the original wins, except for the changes listed in the Sources section below under "Changes for coexistence". The source's own command prompts (its slash commands and Codex skills) are not packaged; their instructions are quoted in steps 1 to 3.
1. **Report (read-only).** Run the matching command and "show me its output verbatim in a code block".
   - `$TE status`: what it learned and did here, and what the sessions cost. "Add nothing unless the output contains a warning, in which case explain the warning in one sentence."
   - `$TE microskills`: the facts it injects and those still forming. Show the output "with no commentary".
   - `$TE repos` (`repos list`): every repository it keeps state for. "If the list shows state recorded by an earlier version, say in one sentence that it is sorted out at the next session start, or now with" `repos migrate`.
   - `$TE doctor`: "check Python, the state directory, the agents found, how this directory was identified, and the error log".
   - `$TE config show`: "what is on, and every value in effect".
2. **Tool pruning.** `$TE toolprune show` is the default: "it shows the proposal when there are none" of the other arguments. "Use `show` as ARGS unless the user asked to `apply`, `restore` or `measure` (optionally naming capabilities). Never run `apply` or `restore` unless the user asked for it." It applies or restores the deny list only when the user asked for `apply` or `restore`; "never add them yourself". `refresh-catalog` records the tools a session loads (Claude Code, Copilot). `apply` and `restore` edit the project's host settings (Claude Code: `.claude/settings.local.json`; Codex: `.codex/config.toml`; Copilot: `.github/copilot/settings.local.json`). "`toolprune measure` on Claude Code makes its two calls the same way" (model calls through `claude -p`), "and only when you run it". "If the output is a proposal, end with one line telling me how to apply it" (here: ask this capability to apply it, which runs `$TE toolprune apply`) "and that it takes effect from the next session."
3. **Settings.** "Use `show` as ARGS unless the user asked to change a setting; then `set KEY=VALUE ...` or `unset KEY ...`, adding `--global` only if they asked for every repository." It changes a setting only when the user asked for `set` or `unset`; "never add them yourself. If a setting was rejected, say why in one sentence." The keys and their values are in the README's `## Settings`; the three mechanisms are `microskills` (`on`, `off`, `envfacts`, `distiller`; off by default), `toolprune` (`on`/`auto`, `off`, `propose`) and `loopguard` (`on`/`nudge`, `off`). For repositories: "Use `list` as ARGS unless the user asked to `migrate`, or to `merge KEY [INTO]` (keys as the list shows them; INTO defaults to this repository). Never run `migrate` or `merge` unless the user asked for it." "a merge keeps the old state directory under `~/.tokeneconomizer/merged/`."
   - On Codex, for `config set`, `config unset`, `repos migrate`, `repos merge`, `toolprune apply` and `toolprune restore`, the source says: the command "writes TokenEconomizer's own state under `~/.tokeneconomizer`, outside the workspace, which the sandbox keeps read-only: run that command with `sandbox_permissions` set to `"require_escalated"` and a one-line `justification`, so that Codex asks the user to approve it." `show`, `list` and `measure` need no approval.
4. **Automatic mode on** (only when the user asks to activate it). The mechanisms run only when the host calls the dispatcher on its hook events. This plugin never registers them by itself.
   - First say, in plain words, what activation does: the dispatcher runs at session start and end, on every prompt and on every tool call; state is kept in `~/.tokeneconomizer`; with the defaults tool pruning writes a deny list to the project's host settings after the repository's sessions have been idle for 60 minutes (`toolprune=propose` only proposes); the loop guard may call a judge model through the user's own agent command line (`claude -p` and the like), billed where their session is, sending digests ("command templates, edited file basenames, error lines with paths and numbers masked, never file contents"); micro-skills is off by default.
   - Say what this release was verified on by its authors: Claude Code 2.1.300 to 2.1.310, Codex 0.153.1 to 0.164.0, Copilot CLI 1.0.83 to 1.0.102, Pi 1.2.0 to 1.3.0, and that it lists Windows as a limitation. Compare with the host's actual version and name any gap.
   - After the user confirms, add the entries of `<package_root>/scripts/tokeneconomizer/plugin/hooks/hooks.json` (Codex: `codex-hooks.json`; Copilot: `copilot-hooks.json`) to the project's host settings: six events, five in the Codex manifest, which has no `PostToolUseFailure`. Keep each entry's timeout and the arguments the manifest puts after the launcher (`--host codex`, `--host copilot`), and replace the launcher itself with `python "<package_root>/scripts/tokeneconomizer/plugin/scripts/te_bootstrap.py" hook`, with `<package_root>` written out as the absolute path. On Claude Code the file is `.claude/settings.local.json`. Merge into what is there; refuse to write a file that does not parse. Tell the user it takes effect from the next session.
5. **Automatic mode off.** Remove exactly the entries that point at this plugin's `te_bootstrap.py`, nothing else. The learned state stays in `~/.tokeneconomizer` ("Uninstalling the plugin leaves this directory; delete it to forget"); deleting it is the user's call. For one session only, `TE_DISABLE=1` in the environment "turns the whole plugin off".

## Specifics

- Without the automatic mode the commands work but have nothing new to show: "The plugin learns from a session once it ends", through its hooks.
- If the original TokenEconomizer plugin is also installed in the host, its hooks and these would both run. One of the two must be off.
- The hook entries hold an absolute path to this plugin's folder. After this plugin is updated or moved, run activation again so the path is current; a stale path makes the hook fail and the session carries on.
- "Every hook fails open: any error becomes an empty output (no change) and a traceback in `~/.tokeneconomizer/errors.log`." When "the hooks seem to do nothing", run `$TE doctor` "and read its errors.log lines".
- "The deny-list writer adds and removes only deny rules it recorded adding, never one you wrote". "`toolprune restore` gives back what the plugin removed, and only that; what you give back is never removed again (`toolprune apply NAME` removes one again)."
- "A learned fact is text injected into your agent's context, derived from your sessions' command output — which a repository controls." "On a repository you do not trust, use `microskills=envfacts`, or read what it learned with `te microskills`" (here `$TE microskills`).
- The source's supported-versions table is in its root `README.md`, which is not packaged; step 4 carries its four rows.
- Runtime dependency: Python 3.10 or newer, already required to run this coordinator. Nothing is installed.

## Checks

- **output_shown_verbatim**: the command's output is shown as it was printed, with the command that produced it.
- **no_change_without_explicit_request**: no `apply`, `restore`, `set`, `unset`, `migrate`, `merge` or hook edit ran unless the user asked for that action in this task.
- **activation_effects_disclosed_before_registering**: before any hook entry was written, the user was told about the hook events, the state folder, the automatic deny list, the judge's model calls and the verified host versions, and confirmed.
- **hooks_registered_or_removed_exactly**: the settings file parses after the edit and contains exactly the entries of the host's manifest (six; five on Codex) pointing at this plugin's dispatcher (activation) or none of them (deactivation), with every other entry unchanged; when nothing was registered or removed, record this as not applicable.
