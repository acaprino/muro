# Paper Figure

Publication figures for a paper in two modes: an editable draw.io diagram, or a matplotlib plot. `<DP>` is `<package_root>/scripts/open-paper-skills/skills/drawio-paper`. `<DP>/SKILL.source.md` (below "the pipeline skill") frames both modes; `<package_root>/scripts/open-paper-skills/skills/codex-paper-figure-skill/SKILL.source.md` (below "the figure skill") adds to diagrams. They are the full version of this method: where this body differs from an original, the original wins, except for the changes listed in the Sources section. Open only the sections a step names, for the mode at hand. `{skill_dir}` in the pipeline skill is `<DP>`.

## Behavior

1. **Mode.** Methodology text with a figure caption, or a figure description or concept without data, is a diagram; raw data (table, JSON, CSV) with a visual intent is a plot; if ambiguous, ask which. Beyond that, ask at most one concise clarification, only when the missing detail changes the figure type or the scientific meaning; otherwise infer a sensible academic format from the text.
2. **Brief.** Parse the input into the scientific message (the single claim or workflow to communicate), the entities, their relationships, the labels that must appear verbatim (paper terms, abbreviations, axes, panel letters, conditions, units) and the constraints (journal style, aspect ratio, palette, panels, export format, editability).
3. **Reference pass.** Before generating, always look at reference images of the benchmark dataset. Check that `{skill_dir}/PaperBananaBench/diagram/ref.json` and `{skill_dir}/PaperBananaBench/plot/ref.json` both exist; if either is missing, set the dataset up (Specifics). Read `ref.json` and `test.json` of the mode's folder, select 3-5 relevant references and view them from its `images/` folder, noting their visual patterns. Priority: same topic and same visual intent, then same visual intent, then same topic.
4. **Plan.** Write a description as detailed as possible, with the contents the pipeline skill lists under "Stage 2: Planning". A diagram plan labels every element; a plot plan enumerates every raw data point's coordinate explicitly and gives exact aesthetic parameters (HEX colours, font sizes, line widths, grid style).
5. **Style.** Refine the plan with the style guide of the mode: `<DP>/neurips2025_diagram_style_guide.md` or `<DP>/neurips2025_plot_style_guide.md` ("Stage 3: Style Refinement" of the pipeline skill gives their key principles in short). For a diagram also apply the figure skill's "Figure Design Rules". For a plot, specify visual attributes without altering data content. No figure caption text goes inside the figure, in either mode.
6. **Raster reference (diagram).** When the host has an image generation tool it may use for this task, generate one raster reference first, prompted as the figure skill's "Workflow" step 3 says (a clean academic-paper figure, not a marketing illustration; labels in the image are approximate). It is a composition guide only, never the sole deliverable when editable output was asked. Without such a tool, skip this step and say so in `figure_review`.
7. **Generate.**
   - Diagram: always a native `.drawio` file in mxGraphModel XML, never Mermaid or CSV as the final editable format. Root cells `<mxCell id="0"/>` and `<mxCell id="1" parent="0"/>`; a unique `id` for every `mxCell`; `&amp;`, `&lt;`, `&gt;`, `&quot;` escaped in attribute values; `html=1` in the style whenever `value` uses HTML formatting; every edge has a child `<mxGeometry relative="1" as="geometry"/>`; no XML comments; labels are real draw.io text, not raster text. Keep at least 200px horizontal and 120px vertical gap between major groups and align all nodes to multiples of 10. Open "Stage 4A: Draw.io XML Generation (Diagram mode)" in the pipeline skill for the remaining layout rules, font sizes, design patterns, palette and XML snippets, and its closing sections "Common styles reference", "Edge routing" and "Containers and groups" when you need a style keyword or a container.
   - Plot: one complete script that runs on its own, with all data embedded in the code (no external reads unless the user explicitly provides a file path). `matplotlib.use('Agg')` before importing pyplot; `plt.rcdefaults()` before setting custom styles; save as PNG at 300 DPI with `bbox_inches='tight'` and `facecolor='white'`, then `plt.close('all')`; never `plt.show()`. Open "Stage 4B: Python/Matplotlib Code Generation (Plot mode)" for the style template, palettes, chart-type code patterns and common pitfalls. Then write the `.py` file, run it, check that the image was created and, on failure, read the error, fix the code and re-run (up to 3 attempts).
8. **Icons (diagram).** Use icons only when they improve recognition or reduce clutter. Either Unicode or emoji characters as text cells (tables under "Semantic icons as text labels" in the pipeline skill), or downloaded icons: open the figure skill's "Icon Workflow" and follow its seven steps with the host's browser on `https://www.flaticon.com/`. Download only after the license and attribution requirement are clear; when licensing is not usable or the download is unreliable, draw a simple editable shape instead. Each icon stays a distinct movable image element. Record icon source URLs, author and attribution or license notes in the final response and in any README or example output that uses them.
9. **Critique and refine.** Apply the list of the mode from "Stage 5: Critique and Refinement" in the pipeline skill. Diagram: content fidelity, text QA, layout clarity, style compliance, caption exclusion, legend management; also confirm that every entity and relationship of the brief is represented, that text is editable, legible and not overlapping, and that arrows and panel order match the paper's logic. Plot: faithfulness, conciseness, readability, aesthetics. If issues are found, revise the XML or the code and regenerate or re-execute.
10. **Deliver.**
    - Diagram: deliver the editable `.drawio` file unless the user asks for another format; with no format mentioned, write the `.drawio` file and open it. For PNG, SVG or PDF, first create the `.drawio` file, then export with the diagram XML embedded: `drawio -x -f <format> -e -b 10 -o <output> <input.drawio>`. The `.drawio` source is kept after an export. When the CLI is available, export a preview and inspect it for blank canvas, clipping and layout issues. Never present a raster-only image as complete when an editable figure was asked.
    - Plot: `.png` at 300 DPI by default; for PDF or SVG change the `format` parameter of `plt.savefig()`. The image sits beside `name.py`; keep both.
    - Names: descriptive, lowercase with hyphens; exports carry double extensions (`name.drawio.png`, `name.drawio.svg`).
    - Open the result with `open <file>`, `xdg-open <file>` or `start <file>`; on a host with no desktop, give the path instead.

## Specifics

- Runtime dependency, references: PaperBananaBench (Apache-2.0, about 266 MB). Run `curl -L -o "{skill_dir}/PaperBananaBench.zip" https://huggingface.co/datasets/dwzhu/PaperBananaBench/resolve/main/PaperBananaBench.zip`, then `python "{skill_dir}/scripts/extract_bench.py"` (packaged as `<DP>/scripts/extract_bench.py`), and say in one line what is downloaded, its size and where. If the download fails, retry or ask the user to download the file by hand, place it at that path and run the extraction. On Windows some over-long image names are skipped; the script says only the JSON index files are required. If the dataset still cannot be had, or the user objects to the download, work from the two style guides and record the reference pass as not done.
- Runtime dependency, plots: Python with `matplotlib`, `numpy` and `pillow`. The source gives `pip install matplotlib numpy pillow`; install the missing ones for the project's environment (`pip install` or `uv pip install`) and say so.
- Runtime dependency, exports: the draw.io desktop application. Try `drawio` first, then the platform path: macOS `/Applications/draw.io.app/Contents/MacOS/draw.io`, Windows `"C:\Program Files\draw.io\draw.io.exe"`. When it is missing and an export is asked, install it from github.com/jgraph/drawio-desktop releases and say so. If it still cannot be found, keep the `.drawio` file and clearly report that the export was skipped; never replace it with another renderer.

## Checks

- **reference_pass_done_or_reported**: reference figures were viewed before planning, or the answer says the dataset was unavailable and why.
- **content_matches_source_text_or_data**: every entity, relation and verbatim label from the brief is in the diagram; every data value and axis label in the plot equals the input.
- **file_well_formed_and_runs**: the `.drawio` XML parses and has the root cells, or the script ran and produced the image.
- **export_inspected_or_reported**: an export was opened and checked for blank canvas, clipping and overlap, or it is reported as skipped or not inspected.
- **critique_round_done**: the critique list for the mode was applied and its findings are in `figure_review`.
