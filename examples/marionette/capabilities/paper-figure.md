# Paper Figure

Publication figures for a paper in two modes: an editable draw.io diagram, or a matplotlib plot. `<DP>` is `<package_root>/scripts/open-paper-skills/skills/drawio-paper`. The second skill is under `<package_root>/scripts/open-paper-skills/skills/codex-paper-figure-skill/`.

## Behavior

0. **Read the originals first.** Read `<DP>/SKILL.source.md` whole before working: for a plot its "Stage 4A: Draw.io XML Generation (Diagram mode)" and the sections from "draw.io CLI" to the end may be skipped, for a diagram its "Stage 4B: Python/Matplotlib Code Generation (Plot mode)" may be skipped. For a diagram also read `<package_root>/scripts/open-paper-skills/skills/codex-paper-figure-skill/SKILL.source.md` whole. Read the style guide of the mode whole: `<DP>/neurips2025_diagram_style_guide.md` or `<DP>/neurips2025_plot_style_guide.md`. These files are the method in the sources' own words, with the XML patterns, palettes, icon tables and code templates. Where this body and an original differ, the original wins, except for the changes listed in the Sources section below under "Changes for coexistence". `{skill_dir}` in the first file is `<DP>`. The steps below are an index into the two skills; sentences in quotation marks are theirs.
1. **Mode** (drawio-paper "Mode detection"). "If the user provides **methodology text + figure caption** → Diagram mode"; "If the user provides **raw data (table/JSON/CSV) + visual intent** → Plot mode"; "If ambiguous, ask the user which mode they want". A figure description or concept without data is a diagram (codex-paper-figure-skill "Overview"). After that: "Ask at most one concise clarification only when the missing detail changes the figure type or scientific meaning. Otherwise infer a sensible academic figure format from the source text."
2. **Brief** (codex-paper-figure-skill "Workflow" 1). "Parse the user's text into a figure brief": "Scientific message: the single claim or workflow the figure should communicate."; "Entities"; "Relationships: sequence, causality, comparison, hierarchy, feedback, input/output, or spatial organization."; "Required labels: paper terms, abbreviations, axes, panel letters, conditions, and units that must appear verbatim."; "Constraints: target journal style, aspect ratio, color palette, number of panels, export format, and whether the output must be editable."
3. **Reference pass** (drawio-paper "Setup" and "Stage 1: Reference Retrieval"). "Before generating, **always** look at reference images from the benchmark dataset to understand the visual style expected." "Check if `{skill_dir}/PaperBananaBench/diagram/ref.json` and `{skill_dir}/PaperBananaBench/plot/ref.json` both exist." If either is missing, install the dataset as Specifics says. Read `ref.json` and `test.json` of the mode's folder (`diagram/` or `plot/`), "select 3-5 relevant reference images to study" and view them from its `images/` folder. "**Priority:** Same Topic + Same Visual Intent > Same Visual Intent > Same Topic". Note the visual patterns the source lists for the mode.
4. **Plan** (drawio-paper "Stage 2: Planning"). "The description should be **as detailed as possible**". Diagram: "All components and their relationships", "Data flow direction (typically left-to-right or top-to-bottom)", "Grouping/containment hierarchy", "Labels for every element", "Mathematical notation where appropriate". Plot: "Precise mapping of variables to visual channels (x-axis, y-axis, hue/color, size, shape)", "Explicitly enumerate **every raw data point's coordinate** to ensure accuracy", "Chart type selection and justification", "All axis labels, tick values, and units", "Legend content and placement", and the "**exact aesthetic parameters**" it lists (HEX colour codes, font sizes, line widths, grid style, legend placement).
5. **Style** (drawio-paper "Stage 3: Style Refinement"; for a diagram also codex-paper-figure-skill "Figure Design Rules"). Apply the style guide of the mode to the plan, with the key principles, domain-specific styles and chart-type guidelines the source lists. Plot: "Focus on specifying visual attributes without altering data content." Both modes: no figure caption text inside the figure.
6. **Generate.**
   - Diagram (drawio-paper "Stage 4A" and "CRITICAL: XML well-formedness"; codex-paper-figure-skill "Workflow" 4 and "Draw.io Generation Rules"). "Always create a native `.drawio` file in mxGraphModel XML. Do not use Mermaid or CSV as the final editable format." Root cells `0` and `1`; "Use unique `id` values for every `mxCell`."; "Escape special characters in XML attributes: `&amp;`, `&lt;`, `&gt;`, and `&quot;`."; "Always set `html=1` in style when using HTML formatting in `value`"; "Edges must contain a child geometry element such as `<mxGeometry relative="1" as="geometry"/>`."; "Do not include XML comments in generated `.drawio` files."; "Keep labels as real draw.io text, not embedded raster text." Layout: "At least 200px horizontal gap, 120px vertical gap between major groups"; "Align all nodes to multiples of 10"; the other layout rules, font sizes, palette and patterns are in "Stage 4A".
   - Plot (drawio-paper "Stage 4B"). "The generated Python code must be a single, complete script that can run independently. All data must be embedded directly in the code (no external file reads)." "`matplotlib.use('Agg')  # Headless backend - MUST be before pyplot import`"; "Always call `plt.rcdefaults()` before setting custom styles to avoid inheriting stale state."; "Save the plot as PNG at 300 DPI with tight bounding box" on a white face, then `plt.close('all')`; "Never use `plt.show()`. Always use `plt.savefig()` only." Then the source's "Code execution workflow": write the `.py` file, execute it, "**Check** that the output `.png` file was created successfully", "If execution fails, read the error, fix the code, and re-execute (up to 3 attempts)". Its "Common pitfalls to avoid" apply.
7. **Raster reference (diagram)** (codex-paper-figure-skill "Workflow" 3). When the host has an image generation tool it may use for this task, generate one raster reference before step 6: "Prompt for a clean academic-paper figure, not a marketing illustration."; "Include the exact figure structure, panel layout, visual hierarchy, palette, and domain-specific objects."; "Request simple legible labels only when needed, but treat labels in the generated image as approximate because raster text may be imperfect."; "Use the generated image as a composition guide only; do not deliver it as the sole final figure when the user asked for editable output." Without such a tool, skip this step and say so in `figure_review`. "Never present a raster-only image as complete when the user requested an editable academic figure."
8. **Icons (diagram).** Two ways, both the sources': Unicode or emoji characters as text cells (drawio-paper "Semantic icons as text labels", with its reference tables), and downloaded icons (codex-paper-figure-skill "Icon Workflow", seven steps, with the host's browser on `https://www.flaticon.com/`). "Use icons only when they improve recognition or reduce clutter." "Download the icon only after the license and attribution requirement are clear". "Avoid premium, locked, login-required, or unclear-license icons. If licensing is not usable or the icon cannot be downloaded reliably, create a simple editable draw.io shape instead." "In draw.io, keep each icon as a distinct movable image element. Do not flatten icons into a background image." "Record icon source URLs, author, and attribution/license notes in the final response and any README/example output that uses external icons."
9. **Critique and refine** (drawio-paper "Stage 5: Critique and Refinement"; codex-paper-figure-skill "Workflow" 5). Diagram: the six points "Content fidelity", "Text QA", "Layout clarity", "Style compliance", "Caption exclusion", "Legend management"; "If issues are found, revise the XML and regenerate." Also "Confirm all scientific entities and relationships from the brief are represented.", "Confirm text is editable, legible, and not overlapping.", "Confirm arrows and panel order match the paper logic." Plot: the four dimensions "Faithfulness", "Conciseness", "Readability", "Aesthetics", each with the questions the source lists; "If issues are found, revise the Python code and re-execute."
10. **Deliver** (drawio-paper "Output workflow", "Choosing the output format", "draw.io CLI", "File naming"; codex-paper-figure-skill "Output Contract").
    - Diagram: "Deliver the editable `.drawio` file unless the user asks for another format." "If no format is mentioned, write the `.drawio` file and open it." "If the user requests PNG, SVG, or PDF, first create the `.drawio` file, then export with draw.io CLI using embedded diagram XML when available": `drawio -x -f <format> -e -b 10 -o <output> <input.drawio>`. "If draw.io CLI is available, export a preview and inspect it for blank canvas, clipping, and layout issues." The `.drawio` source is kept after an export (see "Changes for coexistence").
    - Plot: "Default output is `.png` at 300 DPI. For PDF/SVG, change the `format` parameter in `plt.savefig()`." "Output `name.png` (or `.pdf`/`.svg`) alongside `name.py` (the source script). Keep both files".
    - Names: "Use descriptive filenames based on content"; "Lowercase with hyphens for multi-word names"; "For export: double extensions (`name.drawio.png`, `name.drawio.svg`)."
    - "Open the result" with `open <file>`, `xdg-open <file>` or `start <file>` as the source says; when the host has no desktop to open it on, give the path instead.

## Specifics

- Runtime dependency, references: PaperBananaBench (Apache-2.0, about 266 MB). The source's setup, with `{skill_dir}` being `<DP>`: `curl -L -o "{skill_dir}/PaperBananaBench.zip" https://huggingface.co/datasets/dwzhu/PaperBananaBench/resolve/main/PaperBananaBench.zip`, then `python "{skill_dir}/scripts/extract_bench.py"`, which extracts beside it. Say in one line what is downloaded, its size and where. "If the download fails due to network issues, retry or ask the user to manually download" the file from that address "and place it at `{skill_dir}/PaperBananaBench.zip`, then run the Python extraction step". "After setup, `{skill_dir}/PaperBananaBench/diagram/` and `{skill_dir}/PaperBananaBench/plot/` should each contain `ref.json`, `test.json`, and an `images/` folder with reference images". On Windows some image names exceed the path limit and are skipped; the script says "only the JSON index files are required for the skill to function correctly". If the dataset still cannot be had, or the user objects to the download, work from the two style guides and record the reference pass as not done.
- Runtime dependency, plots: Python with `matplotlib`, `numpy` and `pillow`. The source gives `pip install matplotlib numpy pillow`; install the missing ones for the project's environment (`pip install` or `uv pip install`) and say so.
- Runtime dependency, exports: the draw.io desktop application. "Try `drawio` first, then fall back to platform-specific path": macOS `/Applications/draw.io.app/Contents/MacOS/draw.io`, Linux `drawio`, Windows `"C:\Program Files\draw.io\draw.io.exe"`. When it is missing and an export is asked, install it from github.com/jgraph/drawio-desktop releases and say so. "If draw.io CLI is not installed or cannot be found, keep the `.drawio` file and clearly report that export was skipped."; never replace it with another renderer.

## Checks

- **reference_pass_done_or_reported**: reference figures were viewed before planning, or the answer says the dataset was unavailable and why.
- **content_matches_source_text_or_data**: every entity, relation and verbatim label from the brief is in the diagram; every data value and axis label in the plot equals the input.
- **file_well_formed_and_runs**: the `.drawio` XML parses and has the root cells, or the script ran and produced the image.
- **export_inspected_or_reported**: an export was opened and checked for blank canvas, clipping and overlap, or it is reported as skipped or not inspected.
- **critique_round_done**: the critique list for the mode was applied and its findings are in `figure_review`.
