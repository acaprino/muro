# Design Tips (twenty practical checks, build and review)

Walks twenty small decisions that separate a screen that looks designed from one that looks assembled. `<DT>` below stands for `<package_root>/scripts/charles-skills/skills/drops/charles-design-tips`. The method is `<DT>/SKILL.source.md`: each tip has its numbers, its reason and a check. Open a tip's section when a step reaches it. The original is the full version and wins where this body differs, except for the changes listed in the Sources section. The tips are defaults: when one is broken on purpose, say which one and why.

## Behavior

1. **Match the stack** (`## Run it`). Find how the project styles things (Tailwind, CSS variables, CSS Modules, a component library's theme) and make every fix there. When the project has tokens of a kind (colours, line heights, shadows, spacing), every fix of that kind changes or adds a token; one-off values only for kinds it has no tokens for. The first bullet of Specifics limits this where the token's value is recorded.
2. **Take stock** before changing anything: every text style (size, weight, line height, alignment), every grey and brand colour, every box with text in it, every big text with a short line under it, every heading, every row that holds a destructive action, and every form, table, empty state and landing page. This list decides which tips run.
3. **Walk the six areas in order**, type first because the spacing tips measure from it, checking every item of the stock against every tip that applies to it (the tips keep the source's numbers, which are not in walking order):
   - **Type** (`## Type`): 1 left-align text past two lines; 3 body text at weight 400; 6 headings and display text at line height 1.1–1.3, body text and labels 1.4–1.5, control text 1.4; 10 mixed sizes on one line align on the baseline.
   - **Spacing and layout** (`## Spacing and layout`): 2 a control's height is 2 × 1.4 × its font size; 13 twice as much padding at each side as at top and bottom; 15 headings 48px above and 8px below by default, never less than twice as much above as below; 18 stacked text spaced by the smaller text's font size; 5 Delete at the opposite end from Save.
   - **Color** (`## Color`): 4 no pure grey, shifted slightly toward blue, and greys already tinted on purpose toward a warm brand stay; 9 on a coloured background white text at 4.5:1 or a dark shade of the background's own scale; 12 one hue across the shades of a colour, with its three conditions for a deliberate exception; 16 in the dark theme chroma lowered by 20–30% at the same hue; 7 shadows as three small layers, no blur over 28px and no opacity over 0.16.
   - **Components and forms** (`## Components and forms`): 11 a visible label above every field; 17 quantity columns right-aligned with `tabular-nums`.
   - **Copy** (`## Copy`): 8 sentence case; 14 button labels that say the outcome, verb first, with the amount when money moves.
   - **States and pages** (`## States and pages`): 19 every empty state has what is empty, one line on why and one button chosen by the section's tree; 20 only in the hero and CTA sections of landing and marketing pages, the main CTA's font size multiplied by 1.7.
4. **Measure, never eyeball.** Read rendered values in px and colours in hex and OKLCH. In a code-only review, take anything the code does not set from the browser's default styles and say so in the finding.
5. **Verify** with the eight checks of `## Verify`, the first of which renders the screen at its real size and at 375px wide, in every theme it has. Run every check you can; in a code-only review compute what the code allows without creating files, and after the findings list the checks you could not run and what each would catch.
6. **Build** (`ui.design-tips`): the change, made in the project's tokens and components, then one line per tip applied (the tip, where, before → after) and one per tip broken on purpose, with the reason (`## Deliver`).
7. **Review** (`ui.design-tips-review`): change nothing. Open with the stock list, then one table row per finding (Severity, Tip, Where, Before, After; one row names both tips when one value breaks two), sorted by severity, then by tip number, with the source's default severity for each tip (`## Run it`, "Reviewing instead of building?"). Problems no tip covers go in a list after the table, then the checks you could not run.
8. **Record** `tips_changes` (files and what changed, by tip; `none` for a review) and `tips_report` (the review, or for a build the tips broken on purpose, what was reported instead of changed and the checks not run).

## Specifics

- **A recorded system is deliberate.** A token whose value traces to a project `DESIGN.md` that is not a starter or a reference, to a design-system Master in the repository, to a recorded `palette`, `typography`, `aesthetic_direction` or `constraints`, or to the client's brand is not changed here: the tip is reported with its before and after, as a tip broken on purpose by that system, and the design file is never rewritten in this step (`design-file` owns it). Tokens the project defines with no such record are changed as the source says.
- **Severity** (`## Run it`): **broken** when someone can hit the wrong action, lose track of what they are typing or get stuck; **friction** when it is slower to read, scan or decide than it needs to be; **polish** when it looks off and slows no one.
- **Beside design guidance.** A recorded `design_candidates` or `stack_guidance` is a set of proposals. The lookup data gives 1.5–1.75 for body line height where tip 6 gives 1.4–1.5: 1.5 satisfies both, and any other difference is named in the report with both values.
- **Beside the other steps of the package.** Tip 4 tints greys toward blue unless they lean toward a warm brand on purpose; the colour critique asks neutrals to lean toward the palette. Tip 7 keeps shadow layers black at low opacity, or the project's own dark ink. Tip 2 extends a touch control's hit area to 44px. Where another step of the same plan recorded a different value for the same thing, name both and change nothing that step owns.
- Motion and interaction states are not covered by these tips. Nothing is installed.

## Checks

- **stock_taken_first**: the stock list was written before any change or finding and decided which tips ran.
- **areas_walked_in_order**: the six areas were walked in order, type first, every stock item against every tip that applies to it.
- **values_measured_not_eyeballed**: findings and fixes quote rendered or computed values in px and colours in hex and OKLCH; a value taken from a browser default is said to be one.
- **fixes_in_project_tokens**: every fix was made in the project's own styling system, in a token where the project has tokens of that kind.
- **deliberate_breaks_named**: each tip broken on purpose is named with its reason.
- **recorded_system_respected**: no value of a recorded system, project design file, Master or client brand was changed; what conflicts with it is reported.
- **findings_in_source_table**: the review opens with the stock list and every finding is a row with severity, tip, where, before and after; no file was changed.
- **unrun_checks_listed**: every check of the verification that could not be run is listed with what it would catch.
