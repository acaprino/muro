# Design Review (audit and fix)

Reviews a design the host can read and edit (HTML, CSS, script or component markup) and fixes what it finds: one pass when the user asks for one, all four as the last gate before delivery. `<CD>` below stands for `<package_root>/scripts/claude-design-system-prompt/claude/skills`. Each pass has its full version in one file there; open the file of a pass when that pass runs, and no other. The file wins where this body differs, except for the changes listed in the Sources section.

## Behavior

1. **Fix the surface.** Review the file the user just edited, finished or asked about; failing that, the most recently modified design file (generic-look pass: the files modified this session; polish pass: the project's main deliverable); if unclear, ask. Read it end to end with the styles, tokens and components it references, so that actual values resolve. Note the medium (slide, page, mobile, dashboard: the rules vary by it), the framework, any stated constraints and, for a polish pass, the deployment context (internal, customer-facing, marketing). The accessibility level is WCAG AA by default. A polish pass on a design clearly mid-flight (broken layout, missing sections, placeholder content still being iterated) says so and asks whether to polish now or after the structure settles.
2. **Review for coverage.** Report every issue found, including uncertain, borderline and low-severity ones, each with its location and a confidence and a severity estimate; nothing is filtered at this stage. Run the pass of the selected intent, or all four for `ui.polish-pass` (`<CD>/polish-pass.md`, `## Phase 2: Launch four review agents in parallel`, lists what each covers):
   - **Accessibility**: `<CD>/accessibility-audit.md`, `## Phase 2: Launch four review agents in parallel`. Four briefs (contrast and colour; semantic HTML and structure; keyboard navigation and focus; motion, forms and the rest), every numbered item. Minimums: 4.5:1 for normal text (under 18px), 3:1 for large text (18px+ bold or 24px+) and for UI components (buttons, icons, focus rings); report each failing pair with its computed ratio and the required one.
   - **Generic look**: `<CD>/ai-slop-check.md`, `## Phase 2: Single-pass review`. Nine rules in one pass, each a default and the patterns to detect (gradients, emoji, cards, imagery, fonts, pure white on black, untraceable colours, off-scale spacing, the editorial-warm house style). Rules 5 (default fonts) and 9 (house style) question before they replace: never silently swap one generic for another, and for rule 9 replace with the committed direction or flag it when there is none.
   - **Hierarchy and rhythm**: `<CD>/hierarchy-rhythm-review.md`, `## Phase 2: Launch two review agents in parallel`. Seven hierarchy items for every screen, slide or major section (primary / secondary / tertiary, size, colour, weight, position, density, the 5-second test) and seven rhythm items for the document as a whole (spacing scale, type scale, repetition, strategic variation, palette discipline, section structure, alignment).
   - **Interaction states**: `<CD>/interaction-states-pass.md`, from `## Phase 1: Inventory interactive elements` to `## Phase 4: Verify feedback for actions`. Inventory every interactive element; check six aspects on each (default, hover, active / pressed, disabled, focus, loading); then transitions, visible feedback for every action and visible current state.
   Where a file launches review agents in parallel, do that with a `subagents` tool, each agent given the full file contents; without one, run the same briefs in sequence in this step. The agents report; this step fixes.
3. **Aggregate** into one deduplicated list. A polish pass merges duplicates across passes (for example "focus ring removed" from both accessibility and interaction states) and groups: **Blockers**, the accessibility failures (contrast under WCAG, missing keyboard support, removed focus rings, missing labels): fix all. **Quality issues**, generic-look tropes, broken hierarchy, missing interaction states: fix all. **Polish recommendations**, subtler improvements (colour tone shift, spacing-scale tightening): apply when in scope, flag when out.
4. **Fix** directly in the file; the first bullet of Specifics limits this where a recorded system is involved.
   - Borderline cases (contrast at 4.4:1) are fixed anyway: accessibility is the floor, not the ceiling.
   - Where several fixes are reasonable (which font replaces Inter when no brand font is stated), pick the most defensible default and note it so the user can override.
   - A clear false positive or something out of reach (a third-party embed) is noted and skipped.
   - Hierarchy: the fix patterns are in `## Phase 3: Aggregate and fix` of its file. In ambiguous cases lean toward the more aggressive hierarchy: too strong is easier to dial back than too weak to dial up.
   - States: add each missing state or feedback element with the design system's tokens; the fallbacks are under Specifics. Where the right state is not obvious, make a judgment call and note it.
5. **Check the fixes.** Re-check the high-risk areas: did contrast fixes wash out a brand colour? Do the new focus rings overlap neighbouring content? Does the primary CTA now actually feel primary? Fix what looks off; flag what is uncertain.
6. **Record** `review_findings` (by pass and group, with locations) and `review_fixes`: issues found and fixed by category, judgment calls for the user to review, what is left to the user, and what could not be verified (never claim success on unverified work). A polish pass reports concisely under the source's four headings: **Verdict** ("Ready to ship" / "Ready after user reviews flagged decisions" / "Needs more iteration before polish makes sense"); **Blockers fixed and polish applied**, counts by category; **Open decisions**, judgment calls to sign off (font choice, colour tone shift, emphasis level); **Out of scope**, noticed but untouched (copy edits, content additions, new features).

## Specifics

- **A recorded system is deliberate.** Values that trace to a dealt `palette` and `typography`, an `aesthetic_direction`, `design_tokens`, recorded `constraints` or the client's brand are not tropes. A finding against that system is reported to the user, not fixed: those values have another owner.
- **Timing.** A recorded `motion-spec` and `reduced-motion` decide durations and alternatives. Without them the source's values apply: 0.15–0.3s for state changes (hover, focus, active); 0.3–0.5s for entry and exit (modals, drawers, toasts); never over 0.5s on micro-interactions (laggy) and never 0s or no transition (broken); motion-heavy transitions wrapped in `@media (prefers-reduced-motion: reduce)`.
- **Fallbacks when the system defines no state:** hover 10–15% darker (or `color-mix`); active another 10% or `scale(0.98)`; disabled opacity 0.6 + `cursor: not-allowed`; focus `outline: 2px solid var(--color-primary); outline-offset: 2px`; transition `0.2s ease`.
- Pure `#FFFFFF` on `#000000` is a style recommendation in the accessibility pass, not a WCAG failure; rule 6 of the generic-look pass replaces it.
- The source's system prompt sets delivery minimums by medium, which a review also holds: body text never under 24px on 1920×1080 slides, 12pt in print and 16px on mobile, interactive hit targets never under 44×44px; and one primary action per screen.
- An interactive explainer keeps its template's look and a GenOffice deck its own audit: only accessibility findings are fixed in the former, and Office files are not reviewed here.
- The pass adds no content, copy or feature: these are the source's "Out of scope". Nothing is installed.

## Checks

- **surface_read_in_full**: the file and its referenced styles were read whole before any finding.
- **every_finding_located_and_rated**: each finding names its location, severity and confidence.
- **blockers_fixed**: no accessibility failure remains, or each remaining one is listed with the reason.
- **recorded_system_respected**: no value of a recorded direction, palette, tokens or client brand was changed; conflicts with it are reported.
- **fixes_rechecked**: contrast, focus rings and the primary action were checked again after the fixes.
- **unverified_items_disclosed**: what could not be measured or operated without a browser is named as not tested.
