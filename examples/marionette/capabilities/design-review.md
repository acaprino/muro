# Design Review (audit and fix)

Reviews a design the host can read and edit (HTML, CSS, script or component markup) and fixes what it finds: one pass when the user asks for one, all four as the last gate before delivery. `<CD>` below stands for `<package_root>/scripts/claude-design-system-prompt/claude/skills`; the prompt is `<package_root>/scripts/claude-design-system-prompt/claude/system-prompt.md`.

## Behavior

0. **Scope by the selected intent, then read its originals whole before working.** They are the method in the source's own words, and the steps below are an index into them. Where this body and an original differ, the original wins, except for the changes listed in the Sources section below under "Changes for coexistence". A skill file is the review procedure; the chapters of the prompt state the same rules as write-time defaults, and where a chapter and a skill file give different numbers the skill file is the review method. Of the prompt only the chapters named here are read for this capability:
   - `ui.accessibility-audit`: `<CD>/accessibility-audit.md`; chapters `# 9. Color system` and `# 10. Accessibility and inclusivity`.
   - `ui.generic-look-check`: `<CD>/ai-slop-check.md`; chapter `# 6. Aesthetic principles — purposeful visuals`.
   - `ui.hierarchy-rhythm-review`: `<CD>/hierarchy-rhythm-review.md`; chapters `# 7. Visual hierarchy and rhythm`, `# 8. Typography system` and `# 12. Simplicity and one clear CTA`.
   - `ui.interaction-states`: `<CD>/interaction-states-pass.md`; chapter `# 11. Interaction and feedback`.
   - `ui.polish-pass`: `<CD>/polish-pass.md` and the four files above; chapters 6 to 12 as above and `# 16. Quality over quantity`.
   - for every intent: of `# 2. Workflow`, items 5 and 6 of its list, and `# 18. Collaboration and delivery`.
1. **Fix the surface (Phase 1 of the selected skill file).** Which file, and what to note about it, is said there in the source's words, for example polish-pass: "Polish the HTML file the user just finished or asked about; otherwise the project's main deliverable; if unclear, ask. Read it and note the medium (slide / page / mobile / dashboard), the deployment context (internal / customer-facing / marketing), and any stated constraints." and "If the design is clearly mid-flight (broken layout, missing sections, placeholder content still being iterated), say so and ask whether to polish now or after the structure settles." The accessibility level is "WCAG AA by default". Read the file end to end with the styles, tokens and components it references.
2. **Review for coverage.** "**report every issue found, including uncertain and low-severity ones, with a confidence and severity estimate for each.** Coverage is the agent's job; filtering and prioritization happen in Phase 3." Each finding also names its location. The source launches review agents in parallel, each with the full file contents; with a `subagents` tool do that, and without one run the same agent briefs in sequence in this step. The agents report; this step fixes.
   - **Accessibility** (`<CD>/accessibility-audit.md`, Phase 2): every numbered item of its four agents, "Agent 1: Contrast and Color", "Agent 2: Semantic HTML and Structure", "Agent 3: Keyboard Navigation and Focus" and "Agent 4: Motion, Forms, and Misc".
   - **Generic look** (`<CD>/ai-slop-check.md`, Phase 2, "Single-pass review"): its nine rules, each with its "Default" and its detection patterns: "1. Gradients — flat or subtle, on-tone", "2. Emoji — functional or brand-driven only", "3. Cards — shadow, thin border, or background separation", "4. Imagery — real, licensed, or honest placeholder", "5. Type — fonts chosen with intent", "6. Color — subtly toned whites and blacks", "7. Color values — trace to a token or harmonious palette", "8. Spacing — snap to a 4px or 8px scale", "9. The editorial-warm house style — deliberate or absent". Rules 5 and 9 are "Detect & question", not replace: "Don't silently swap one generic for another."
   - **Hierarchy and rhythm** (`<CD>/hierarchy-rhythm-review.md`, Phase 2): the seven items of "Agent 1: Hierarchy review", "For every screen, slide, or major section", and the seven items of "Agent 2: Rhythm review", "For the document as a whole".
   - **Interaction states** (`<CD>/interaction-states-pass.md`): "Phase 1: Inventory interactive elements", "Phase 2: Per-element state verification" ("Check all six aspects for each element": Default, Hover, Active / pressed, Disabled, Focus, Loading), "Phase 3: Verify transitions" and "Phase 4: Verify feedback for actions".
3. **Aggregate.** For one pass, as its own aggregation phase says. For a polish pass (Phase 3): "Merge duplicate findings (e.g., "focus ring removed" from both accessibility and interaction-states). Group into:" "**Blockers** — accessibility failures (contrast under WCAG, missing keyboard support, removed focus rings, missing labels). These break the design for real users; fix all." "**Quality issues** — AI slop tropes, broken hierarchy, missing interaction states. These cheapen the design; fix all." "**Polish recommendations** — subtler improvements (color tone shift, spacing-scale tightening). Apply when in scope; flag when out."
4. **Fix** in the file, as the fix phase of each skill file says. From the source: "Fix every blocker and quality issue directly. For ambiguous fixes (e.g., the design uses Inter but no brand font is stated), pick a defensible default and note it so the user can override. Note and skip clear false positives (e.g., a third-party embed's contrast)."; "For borderline cases (e.g., contrast at 4.4:1), apply the fix anyway — accessibility is the floor, not the ceiling."; "For ambiguous cases, lean toward the more aggressive hierarchy — too-strong is easier to dial back than too-weak to dial up."; "Add each missing state or feedback element using the design system's tokens." The first bullet of Specifics limits this step where a recorded system is involved.
5. **Check the fixes (polish-pass, Phase 4).** "Then re-check the high-risk areas: did contrast fixes wash out a brand color? Do the new focus rings overlap neighboring content? Does the primary CTA now actually feel primary? Fix what looks off; flag what you're unsure about."
6. **Record** `review_findings` (by pass and group, with locations) and `review_fixes`: the summary the skill file asks for (issues found and fixed by category, judgment calls, what is left to the user) and what could not be verified. For a polish pass it carries the source's Phase 5: "**Verdict** — "Ready to ship" / "Ready after user reviews flagged decisions" / "Needs more iteration before polish makes sense"", "**Blockers fixed and polish applied** — counts by category", "**Open decisions** — judgment calls to sign off (font choice, color tone shift, emphasis level)", "**Out of scope** — noticed but untouched (copy edits, content additions, new features)".

## Specifics

- **A recorded system is deliberate.** Values that trace to a dealt `palette` and `typography`, an `aesthetic_direction`, `design_tokens`, recorded `constraints` or the client's brand are not tropes. A finding against that system is reported to the user, not fixed: those values have another owner (see Sources, "Changes for coexistence").
- **Timing.** A recorded `motion-spec` and `reduced-motion` decide durations and alternatives. Without them the source's values apply (interaction-states-pass, Phase 3): "**0.15–0.3s** for state changes (hover, focus, active); **0.3–0.5s** for entry/exit (modals, drawers, toasts)", "Avoid over 0.5s on micro-interactions (laggy) and 0s / no transition (broken)", "Wrap motion-heavy transitions in `@media (prefers-reduced-motion: reduce)`".
- Fallbacks when the system defines no state (interaction-states-pass, Phase 5): "hover 10–15% darker (or `color-mix`); active another 10% or `scale(0.98)`; disabled opacity 0.6 + `cursor: not-allowed`; focus `outline: 2px solid var(--color-primary); outline-offset: 2px`; transition `0.2s ease`."
- Pure `#FFFFFF` on `#000000` is flagged by the accessibility pass as "Style recommendation, not WCAG"; rule 6 of the generic-look pass replaces it.
- An interactive explainer keeps its template's look and a GenOffice deck its own audit: only accessibility findings are fixed in the former, and Office files are not reviewed here.
- The pass adds no content, copy or feature: these are the source's "Out of scope". Nothing is installed.

## Checks

- **surface_read_in_full**: the file and its referenced styles were read whole before any finding.
- **every_finding_located_and_rated**: each finding names its location, severity and confidence.
- **blockers_fixed**: no accessibility failure remains, or each remaining one is listed with the reason.
- **recorded_system_respected**: no value of a recorded direction, palette, tokens or client brand was changed; conflicts with it are reported.
- **fixes_rechecked**: contrast, focus rings and the primary action were checked again after the fixes.
- **unverified_items_disclosed**: what could not be measured or operated without a browser is named as not tested.
