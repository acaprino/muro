# Video Generation

Turns a brief into a video: one clip, or several clips planned as one story and joined into one file. The packaged original, `<package_root>/scripts/supercmo-skills/skills/generating-videos/SKILL.source.md` with `references/direct-route.md` and `references/storyboard-route.md` beside it, is the full version of this method and wins where this body differs from it, except for the changes listed in the Sources section. `$S` below is `<package_root>/scripts/supercmo-skills/skills`. Open a packaged file where a step says so.

## Behavior

1. **Read the media, then the brief.** Run `image_analysis` on each supplied image and `video_analysis` on each supplied video. Write down who is in it, where it is, how it is lit and framed, so the prompt matches it. Skip an image you made this turn or already analysed. For a product URL or photo, open `$S/analyzing-products/SKILL.source.md` and follow it. Then read the brief: how long, what happens, where it will be posted, whether anyone speaks.
   - Where the video has a product, write one description and reuse it unchanged in every storyboard: material and finish surface by surface; its width and height and how it sits against a hand; two to five visual anchors you can verify in the product image; what may be done with each part. Nothing later does anything to the product that is not on that list. Do not write out what the label says.
2. **Pick the model.** `seedance-2.0-fast` is the default, and the storyboard route always runs on it unless the user named a model. Stop at the first that applies: the user named a model; the video takes the storyboard route; Seedance refused the brief (`nsfw` / `ip`) or keeps failing, so take the fallback from the table; a row of the table matches; otherwise the default (if two models tie, the newer one).
   - The table: one unbroken shot longer than 15 seconds, or more than nine reference images → `seedance-2.5`. Spoken dialogue with lip-sync, the tightest prompt-following or top cinematic quality → `veo-3.1-fast`. Editing an existing clip (restyle, add or replace an element, fix on-screen text) or legible on-screen text → `gemini-omni`. One person or character held consistent across references or several shots → `kling-3.0-pro`. An edgy or sensitive subject Seedance would refuse, or the fastest, cheapest draft → `grok-imagine-video`. A high-volume or cost-sensitive batch where top quality is not essential → `wan-2.7`.
   - Then call `list_video_models` for the chosen model and read its modes, aspect ratios, durations, resolutions and media before writing any prompt. Each model validates its own subset.
3. **Choose the route.** One clip covers it when the video runs no longer than the model's longest clip (from `list_video_models`) and holds one continuous shot: take the direct route. It needs more than one clip when it runs longer than that, or the brief needs a cut between shots: take the storyboard route. A UGC video or a product ad is not made here (see the Sources section): say which it is and hand the request back to the coordinator.
   - A supplied image is used as the start frame (the video begins on that exact image) or as a reference (it shows a subject or a style and the video is a new scene). Ask which if the brief does not say. A start frame works for one clip only, and `start_frame_image` cannot be combined with any `reference_*` input. Where a person, a product or a style must match an image that is not the start frame, pass that image as a reference and drop the start frame.
4. **Direct route: one clip.** Open `$S/generating-videos/references/direct-route.md` and follow it to the end. In short:
   - Pick the mode from its table of six (text-to-video, image-to-video, start→end transition, reference image, video-to-video, audio-guided), within what `list_video_models` says the model accepts.
   - Ask, in one message, only for what would change the result and cannot be defaulted: the length, the aspect ratio, whether the clip carries sound, whether a second image is an end frame, start frame or reference, what to keep from a supplied video, what a supplied audio track is for. If the user said not to ask, pick sensible values, say what you picked in one line and carry on.
   - Write one line per beat. Each beat runs two seconds where possible, three at most. Spoken words fit at about two to three words a second. It is one continuous shot, with no cut. With a start frame the first beat opens on that image exactly as it is; with an end frame the last beat finishes on it.
   - Write the prompt: open `$S/writing-video-prompts/SKILL.source.md` with the beats, the duration, the model, the aspect ratio, a script segment if anyone speaks, and the media with what each is for. It returns the prompt and the order it labelled the media in.
   - Call `video_generate` with one request: the prompt, the media in the labelled order, `duration`, `resolution`, `aspect_ratio`, `generate_audio`. Omit `model` to use the default. For several takes of one idea repeat the same request object; for different ideas add one object per prompt. Return the clip's URL and local file path.
5. **Storyboard route: more than one clip.** Open `$S/generating-videos/references/storyboard-route.md` and follow it to the end. Its stages, in order:
   - Ask in one message for what is missing: the total length, the aspect ratio, whether anyone speaks and whether on camera or as a voiceover.
   - Plan the concept: who is in it and where, and anything that shows up in more than one clip. Make each clip as long as the model allows and put the leftover in the last one; if the leftover is shorter than the model's minimum, make the last clip the minimum and let the video run a little long. A primary action (one continuous motion at one object) needs two to three seconds. Nothing finer than a whole hand movement, no state change shown on screen, and state only moves forward. Where anyone speaks: two words a second is the target and three the ceiling, so a 15-second clip carries about 30 to 40 words.
   - Only when someone speaks: write the script by opening `$S/writing-video-scripts/SKILL.source.md`.
   - Show the concept in one message and wait for approval. Nothing is generated before it, and everything after it costs money. Expect edits. If the user said not to ask, say in one line what you are going with.
   - Cast what recurs. A person on camera in more than one clip, with no photo supplied: open `$S/generating-ai-actors/SKILL.source.md` with the person from the approved concept. Any other thing in more than one clip (a product, a prop, an animal) with no photo supplied: one clean image on a plain white background, one `image_generate` call at `1k` unless the user asked for a higher tier. For a real product with no photo, ask for one instead of inventing it.
   - Build the sheets: open `$S/generating-storyboards/SKILL.source.md`, one sheet per clip. A sheet is always `16:9` with vertical panels, whatever ratio the video is delivered in. Show all sheets in one message and wait; where there is a product, ask the user to check it in every panel. Rebuild only the sheet a changed panel is on.
   - Write one prompt per clip: open `$S/writing-video-prompts/SKILL.source.md`.
   - Call `video_generate` once with one request per clip: the prompt, the media as `reference_images`, `reference_videos` and `reference_audios` in the labelled order, `duration`, `resolution`, `aspect_ratio`, `generate_audio`. Every clip uses the same aspect ratio and resolution.
   - When every clip has finished, pass them in order to `video_stitch`. Do not join them by hand. Return the finished video's URL and local file path, and the single clips if the user asks.
6. **Pending is not failure.** A clip that comes back as `{status: "pending", …}` is a job handle: pass that exact handle to `job_status`, and again if it is still pending. Never resubmit a pending clip; that starts a second billed job. If the call timed out with no handle, wait and tell the user it is still processing.
7. **Never regenerate a clip the user did not ask for** on the storyboard route: every re-run is billed again. Hand back what came out, say what looks wrong and wait. If one clip of a batch fails, send a new call with only that request. A wrong sheet is remade alone before its clip is made.
8. **Other failures.** A safety rejection: name a workable stand-in for what tripped the filter and resubmit; if the subject itself is the block, switch to `grok-imagine-video`; after a second rejection tell the user which element is blocked. An explicit error that names a parameter or a limit: correct it and resubmit; otherwise resubmit once, then switch to a fallback model or give the user the error text. `no_provider_configured`: relay the tool's `hint`. For the rest open "Edge cases" in the original and in the route file you followed.

## Output handoff

Resolve `<package_root>` with the `package_root` returned beside these instructions, never against the consumer project. Return `video_clips` as one JSON string: the finished video's URL and local path, the clips in order with their paths when there are several, the model, duration, aspect ratio and resolution used, any clip still pending with its job handle, and what failed or was refused. For a mapped step, submit it through the coordinator's `record` command with the step's `map_id` and `capability`. Do not edit `<state_dir>/map.md` or `<state_dir>/state.json`; the coordinator is their only writer.

## Specifics

- Where files land: the server saves every generated clip, sheet and image into its media output folder, which is the folder named by `SUPERCMO_OUTPUT_DIR` in the server's environment, else `./supercmo-media` under the server's working directory. `video_generate` and `image_generate` take no output folder argument. `video_stitch` takes `output`, a file path; without it the file is `stitched_<N>clips.mp4` in the same folder. Give the user the `path` each tool returns.
- A standalone audio file is not clip audio, which is baked into the picture. Speech is the work of the capability `audio-generation`; say plainly that separate music and effects tracks are not generated here.
- Runtime dependency: `ffmpeg` on the PATH, for `video_stitch` only. The tool checks for it and answers `ffmpeg is not installed or not on PATH.` with the hint `brew install ffmpeg` / `apt-get install ffmpeg`; with `dry_run: true` it runs the same check and joins nothing. The source gives no install method for Windows. Where `video_stitch` cannot run, return the clips in order and say they are not joined.

## Checks

- **model_limits_read_first**: `list_video_models` was called for the chosen model before the prompt was written, and the call's mode, duration, aspect ratio, resolution and media stay within what it returned.
- **approved_before_spend**: the concept, and then every sheet, were shown and approved before any clip was generated; or the user said not to ask and each choice was stated in one line.
- **no_unasked_rerun**: no pending clip was resubmitted, and no clip was generated a second time without the user asking.
- **video_url_and_path_returned**: the finished video's URL and local file path were returned; a video of several clips is one file joined by `video_stitch`, or the clips in order with the statement that they are not joined.
